# Pull Request Checklist

I use this checklist before asking teammates to review my work.

## Before Opening the PR

- [ ] The branch has a clear and focused purpose.
- [ ] Files unrelated to the task were not changed.
- [ ] SQL or code has been tested.
- [ ] Results and assumptions are documented.
- [ ] No passwords, tokens, or private data are included.

## PR Description

A helpful pull request description explains:

- what changed;
- why the change was needed;
- how it was tested; and
- anything the reviewer should check.

## Before Merging

- [ ] Review comments are resolved.
- [ ] Required checks pass.
- [ ] The final diff contains only intended changes.
- [ ] The branch is ready to merge into `main`.

Small, focused pull requests are easier to review and safer to merge.
