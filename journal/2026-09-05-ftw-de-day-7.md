# Journal - 2026-09-05 - Day 7: Spark and Data Quality

## Lesson summary

- SQL describes the transformation, while Spark is the engine that can execute it across many machines.
- PySpark DataFrames use familiar operations such as `.select()`, `.filter()`, `.join()`, `.groupBy()`, and `.orderBy()`.
- Filters and selections are usually cheaper than joins, groupings, distinct operations, and sorting because those may cause a shuffle.
- SQL is still a strong choice for clear relational work. Spark is useful when data or processing needs distributed compute.
- Data quality starts by defining expectations, checking them, recording results, monitoring trends, and acting on failures.
- Common checks include null, unique, range, accepted values, referential integrity, and volume checks.
- A DQ dashboard should quickly show pass rate, failed checks, affected datasets, critical failures, and the last check time.

## My key takeaway

A pipeline running successfully does not automatically mean the data is correct. Reliable data engineering must consider scale, trust, and whether other people can safely depend on the output.
