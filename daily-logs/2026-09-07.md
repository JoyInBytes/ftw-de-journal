## 💡 What I Learned

- A query becomes more accurate when I define what one row represents before joining tables.
- INNER JOIN returns matching records, while LEFT JOIN keeps all rows from the left table.
- GROUP BY should match the level at which the business question needs an answer.
- SQL practice is easier when I break a question into source tables, join keys, filters, and final measures.
- Group meetings are important for aligning table names, responsibilities, and expected outputs.

## ⚠️ Challenge and Fix

- **Challenge:** Complex queries can feel confusing when joins and aggregations are written all at once.
- **Fix:** Built the query step by step: inspect the source, test the join, check row counts, then add the aggregation.

## ✅ Key Assumptions

- Join keys are valid and have compatible data types.
- Aggregations are performed only after the intended row grain is confirmed.
- Team members share updates early when a task may affect another layer.
