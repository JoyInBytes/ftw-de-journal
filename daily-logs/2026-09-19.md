## What I learned

A data-quality assertion is a rule the data must meet. If it fails, I need to find out what happened before deciding how to fix it.

A useful investigation asks:

1. When did the pipeline last work?
2. Which table, rows, or columns are affected?
3. What result did we expect?
4. What result did we get?
5. What do the run logs say?

This helps narrow down whether the problem came from the source data or from a processing step.
