## 💡 What I Learned

- Finalizing a group project requires both completing my own task and making handoffs clear for the team.
- Data-quality results should show the failed rule, affected records or metric, severity, and expected owner.
- A successful GitHub Actions run proves the repository checks passed, but it is different from running the Databricks pipeline itself.
- Databricks jobs can orchestrate notebook tasks, while GitHub Actions can validate code and repository standards before changes are merged.
- Clear README documentation makes the project easier to review, continue, and explain.

## ⚠️ Challenge and Fix

- **Challenge:** It was easy to combine CI/CD validation with actual Databricks execution and assume they were the same step.
- **Fix:** Separated the workflow clearly: GitHub Actions validates the repository; Databricks jobs execute the notebooks and data pipeline.
