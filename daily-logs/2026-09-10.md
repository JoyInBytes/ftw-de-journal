## What I learned

A useful issue report should explain which rule failed, which rows or counts were affected, how serious the issue is, and who should investigate it.

GitHub Actions checks the rules configured for the repository. Databricks jobs run the notebooks and process the data. Passing one does not automatically mean the other succeeded.

A job can run tasks in order. For this project, later tasks need the outputs from earlier tasks: Bronze first, then Silver, then Gold.

Documentation helps another person understand how to run the project and check the results.

## Problem and solution

**Problem:** It was easy to think a successful GitHub check meant the Databricks pipeline had run successfully.

**Solution:** I explained the two steps separately: checking repository changes and running the actual data pipeline.

## Notes to remember

- Test notebooks before scheduling them.
- Set tasks to wait for the earlier tasks they depend on.
- Keep unresolved data-quality findings visible.
